# ocapi

Declare an HTTP endpoint once in OCaml, derive the server, the client and the OpenAPI document.

| Package | Module |
| --- | --- |
| `ocapi` | `Ocapi.Endpoint`: method, path, parameters, body, responses; `Endpoint.Meta` to read them |
| | `Ocapi.Server`: routes and dispatch, `Request.t -> Reply.t` |
| | `Ocapi.Client`: calls with a request, decodes the result; the `Send` effect |
| `ocapi-openapi` | `Ocapi_openapi`: the OpenAPI 3.1 document |
| `ocapi-cohttp-eio` | `Ocapi_cohttp_eio.Server`, `Ocapi_cohttp_eio.Client` |
| `ocapi-jsonschema` | `Ocapi_jsonschema`: schemas from `ppx_deriving_jsonschema` |
| `ocapi-ppx` | `[@@deriving provide, responses, ocapi]`: the declaration from types |

`ocapi` depends on `yojson` only. `Server` and `Client` depend on `Endpoint` only.

`examples/` (not installed):

- `items`: a contract (one module per endpoint, derived with `ocapi-ppx`; the JSON types with
  `ppx_yojson_conv` and `ppx_deriving_jsonschema`), its server and its client as three libraries, with executables for both, and the OpenAPI document generated by
  `dune build` and compared with the checked-in file
- `bearer_auth`: the token as a field of the request, the authenticated user read by the handler
  from an effect
- `in_process`: a `Send` handler that dispatches to routes in the same process, no socket
- `retry`: a `Send` handler stacked inside the transport handler, retrying 5xx and timeouts

## Declare

A request is a record. Providers say where each field travels (path, query, header, cookie, body)
and how to read it back; response cases say how a result is sent and decoded.

```ocaml
open Ocapi

type get = { id : string; verbose : bool }

let string_schema = `Assoc [ "type", `String "string" ]

let item =
  Endpoint.Codec.make ~name:"item" ~schema:string_schema (fun s -> `String s)
    Yojson.Safe.Util.to_string

let error =
  Endpoint.Codec.make ~name:"error" ~schema:string_schema
    (fun s -> `Assoc [ "error", `String s ])
    Yojson.Safe.Util.(fun json -> member "error" json |> to_string)

(* GET /items/{id}?verbose=true *)
let get =
  let open Endpoint.Syntax in
  Endpoint.make ~meth:`GET "/items/{id}" ~tags:[ "Item" ] ~summary:"One item"
    (let+ id = Endpoint.Path.string ~description:"item id" "id" (fun r -> r.id)
     and+ verbose =
       Endpoint.Query.optional ~description:"include details" Endpoint.Value.bool "verbose"
         (fun r -> Some r.verbose)
       |> Endpoint.Provide.require ~responses:[ 400, "verbose is neither true nor false" ]
            (fun _ -> Endpoint.Reply.empty 400)
     in
     { id; verbose = Option.value verbose ~default:false })
    ~responses:
      Endpoint.Response.
        [
          json ~status:200 ~description:"The item" item Endpoint.Prism.ok;
          json ~status:404 ~description:"No such item" error Endpoint.Prism.error;
        ]
```

Providers resolve left to right; the first failure answers the request. Response cases are tried
in declaration order; `Response.json_with_headers` sends headers chosen per response
(`Set-Cookie`, say). A case pairs a codec with a `Prism`: the server takes its value out of the
handler's result, the client puts the decoded value back.

### One endpoint, one module

`Endpoint.Make` takes the same declaration as a module, with the request and result types next
to it. The module is named `Spec` because a functor applied to an anonymous structure cannot
return the types defined in it:

```ocaml
module Get = struct
  module Spec = struct
    type request = { id : string; verbose : bool }
    type nonrec result = (string, string) result
    type body = Endpoint.Provide.body_unread (* body_read after Body providers *)
    type doc = Endpoint.complete

    include Endpoint.Defaults (* hidden, headers, tags, summary, description, operation_id *)

    let meth = `GET
    let path = "/items/{id}"
    let tags = [ "Item" ]
    let operation_id = Some "getItem"
    let provide = (* the providers above *)
    let responses = (* the cases above *)
  end

  include Spec
  include Endpoint.Make (Spec)
end
```

`Server.route (module Get) handler` and `Client.invoke (module Get) request` take it whole;
`Get.endpoint` is the endpoint itself.

### Derived from types

With `ocapi-ppx` (`(preprocess (pps ocapi-ppx))`), the spec is written as its types:

```ocaml
module Get = struct
  module Spec = struct
    include Endpoint.Defaults (* first: what is derived below overrides it *)

    (** One item

        Returns the item with the given id. *)
    type request = {
      id : string;  (** Item id *)
      verbose : bool; [@default false]
      trace : string; [@header "X-Trace"]
    }
    [@@deriving provide ~path:"/items/{id}"]

    type result =
      | Found of item [@status 200]  (** The item *)
      | Not_found of error [@status 404]
    [@@deriving responses]

    let meth = `GET
  end

  include Spec
  include Endpoint.Make (Spec)
end
```

- `[@@deriving provide ~path]` writes `provide`, `path`, `type body` and `type doc`, and from
  the doc comment and the module path `summary`, `description` and `operation_id` (`get`; a
  later `let operation_id = ...` overrides it). A field named in the template is a path
  parameter; others are query parameters unless `[@header "Name"]`, `[@cookie]`, `[@body]` or
  `[@provide e]` (any provider of the field's type) says otherwise. `string`, `int` and `bool`
  have values; a field of type `tag` takes `tag_value`, or `[@value e]`. A missing or invalid
  value answers an empty 400; `[@reject e]` replaces that, e.g.
  `[@reject Endpoint.Provide.require_json ~status:400 error (fun _ -> "invalid")]`.
  `[@default e]` makes a query, header or cookie optional.
- `[@@deriving responses]` writes `responses`, one case per constructor with its `[@status]`:
  an empty body without a payload, else the payload's codec (`item_codec` for `item`, or
  `[@codec e]`; `[@discriminator ("kind", "item")]` as in `Response.json`). Constructor names
  go into `x-ocapi-cases`.
- `[@@deriving ocapi]`, on any JSON type after `yojson` and `jsonschema`, writes `item_codec`
  with `Ocapi_jsonschema.codec`. Unlike `provide` and `responses`, it is not tied to a Spec,
  hence the package's name rather than a generic one.

Doc comments are read as odoc: the first paragraph of the request type's is the summary, as
plain text; the rest, and the comments of fields and constructors, become CommonMark
(`{b x}` is `**x**`, `[x]` is `` `x` ``, `{{:url}x}` a link, lists and code blocks stay). Tags such
as `@param` or `@since` describe the OCaml value and are left out.

A path template that does not match the fields, an `Authorization` header, a constructor without
a status, or an attribute close to one of ocapi's (`[@heder]`, `[@stauts]`) is a compile error at
the field or constructor.

## Serve

```ocaml
let routes =
  [
    get
    |> Server.handle (fun { id; verbose = _ } ->
      if id = "a1" then Ok "the item a1" else Error "not found");
  ]

let () =
  Eio_main.run @@ fun env -> Ocapi_cohttp_eio.Server.run ~net:env#net ~port:8080 (Server.serve routes)
```

`serve` is a plain function: wrap it for what applies to every request. Effect handlers go there,
inside the fiber of the request. `run` listens on the loopback by default; in production, put it
behind a proxy that limits request headers and times out slow clients.

## Call

```ocaml
let () =
  Eio_main.run @@ fun env ->
  let client = Cohttp_eio.Client.make ~https:None env#net in
  Ocapi_cohttp_eio.Client.run ~client ~base:(Uri.of_string "http://127.0.0.1:8080") @@ fun () ->
  match Client.call get { id = "a1"; verbose = true } with
  | Ok (Ok item) -> print_endline item
  | Ok (Error e) -> prerr_endline e
  | Error (`Invalid reason) -> prerr_endline reason
  | Error `Unauthorized -> prerr_endline "unauthorized"
  | Error (`Undeclared r | `Malformed (r, _)) -> Printf.eprintf "HTTP %d\n" r.status
```

`Client.call` writes the record and returns the handler's result, decoded with the endpoint's
cases. When the server changes the contract (a field added, renamed or retyped, a result type
changed), the client stops compiling.

Effects do not cross fibers: call `run` inside each fiber that sends.

## Document

```ocaml
let openapi =
  Ocapi_openapi.document
    ~info:(`Assoc [ "title", `String "Items"; "version", `String "1.0.0" ])
    ~common:Ocapi_cohttp_eio.Server.common
    [ get ]
```

Besides the cases of each endpoint, the document shows what providers declare
(`Provide.require_json` with its schema, `Provide.require ~responses`) and what the transport
answers (`~common`). Descriptions, summaries, tags and codec names are optional: what is left out
is left out of the document, a response without a description gets the reason phrase of its
status, and a codec without a name is written inline.

For generators, `Endpoint.make ~operation_id` names the call (unique in a document), and each
response lists where its cases sit in the handler's result under `x-ocapi-cases`: the prism's
constructor (`Prism.ok` is `Ok`, `Prism.named "Gone"` names your own) with the schema. Cases of
one status are a `oneOf`; with `Response.json ~discriminator:("kind", "item")` on each of them, a
`discriminator` maps each value to its schema.

The document takes only endpoints whose every part has a schema. `Codec.custom`,
`Value.custom` and `Response.unspecified_json` make parts without one: such an endpoint serves
and calls as any other, but passing it to `Ocapi_openapi` is a type error.

With `ppx_deriving_jsonschema` (and `ppx_yojson_conv` for the codec):

```ocaml
type item = { id : string; count : int } [@@deriving yojson, jsonschema]

let item = Ocapi_jsonschema.codec ~name:"item" item_jsonschema yojson_of_item item_of_yojson
```

Shared definitions that schemas refer to as `#/$defs/name` go into the document with
`~schemas:(Ocapi_jsonschema.components definitions)`. `Ocapi_jsonschema.documents ~definitions`
writes each schema as a standalone JSON Schema file, for generators of other languages' types.
